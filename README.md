# DFRobot SEN0140 ROS2 package
This is a ROS2 package for the DFRobot SEN0140 10 DOF Mems IMU Sensor, which consists of:
- ADXL345 accelerometer
- ITG3200 gyroscope
- VCM5883L magnetometer
- BMP280 barometer
More info about the sensor can be found on the [DFRobot wiki](https://wiki.dfrobot.com/sen0140/) or in the [datasheets](datasheets/). All share a single I2C bus and reference frame.

## Usage
1. Clone the repo into the `src` directory of your ROS workspace:
```
cd ~/ros2_ws/src
git clone https://github.com/thelollipopman/sen0140_ros2.git
```

2. Build the package from your ROS workspace:   
```
cd ~/ros2_ws
colcon build --symlink-install --packages-select sen0140_ros2
```

3. Source the setup script from your ROS workspace in a new terminal:
```
cd ~/ros2_ws
source install/setup.bash
```

4. Change the default parameters in the [`config.yaml`](config/config.yaml) as desired. See [Configure](#configure) for more info

5. Launch the ROS node:
```
ros2 launch sen0140_ros2 sen0140.launch.py config:=config.yaml
```
The `config` parameter accepts relative file paths from the [config](config/) directory or absolute file paths.


## ROS2 topics and messages

Message timestamps are generated by the ROS node when the sensor measurements are read over I2C, i.e. `rclcpp::Clock::now()` is called right after the I2C read and assigned to the timestamp. The SEN0140 does not provide hardware measurement timestamps through its exposed interface, so timestamps are not exact sensor acquisition times. User calibration of accelerometer, gyroscope and magnetometer measurements is not currently performed by the package. Measurement covariance/variance fields are also not estimated and are published as unknown.


The ADXL345 acceleration (m/s2) and ITG3200 angular velocity (rad/s) data are published to topic `/imu` as [`sensor_msgs/Imu.msg`](https://docs.ros.org/en/kilted/p/sensor_msgs/msg/Imu.html).
```
std_msgs/Header header
geometry_msgs/Quaternion orientation       # not provided
float64[9] orientation_covariance          # covariance unknown; first element = -1 to indicate orientation is unavailable
geometry_msgs/Vector3 angular_velocity     # rad/sec
float64[9] angular_velocity_covariance     # covariance unknown: zeros
geometry_msgs/Vector3 linear_acceleration  # m/s²
float64[9] linear_acceleration_covariance  # covariance unknown: zeros
``` 

The VCM5883L publishes magnetic field (Tesla) data at topic `/magnetic_field` as [`sensor_msgs/MagneticField Message`](https://docs.ros.org/en/kilted/p/sensor_msgs/msg/MagneticField.html) 
```
std_msgs/Header header
geometry_msgs/Vector3 magnetic_field   # Tesla
float64[9] magnetic_field_covariance   # covariance unknown: zeros
```

The BMP280 publishes temperature (Celsius) data at topic `/temperature` as [`sensor_msgs/Temperature Message`](https://docs.ros.org/en/kilted/p/sensor_msgs/msg/Temperature.html)
```
std_msgs/Header header
float64 temperature     # °C
float64 variance        # variance unknown: zeros
```
It also publishes pressure (Pa) data at topic `/pressure` as [`sensor_msgs/FluidPressure Message`](https://docs.ros.org/en/kilted/p/sensor_msgs/msg/FluidPressure.html)

```
std_msgs/Header header
float64 fluid_pressure  # Pa
float64 variance        # variance unknown: zeros
```



## Configure
Config parameters are in [`config.yaml`](config/config.yaml). The parameters are mainly limited to publishing rate, I2C address, resolution and output data rate, while other lower level modes and settings for the individual sensors are not exposed at the moment.


| Parameter | Type | Default | Description |
| --------- | ---- | ------- | ----------- |
| `i2c_device`                                    | string | "/dev/i2c-1" | I2C device file |
| `imu.frame_id`, `mag.frame_id`, `baro.frame_id` | string | "imu_link"   | IMU frame |
| `imu.publish_rate`                              | double | 200.0        | IMU publishing frequency |
| `accel.address`                                 | int    | 83           | ADXL345 I2C address |
| `accel.output_data_rate`                        | double | 200.0        | 6.25 / 12.5 / 25 / 50 / 100 / 200 / 400 / 800 / 1600 / 3200 Hz |
| `accel.range`                                   | int    | 16           | ±2/4/8/16 g|
| `gyro.address`                                  | int    | 104          | ITG3200 I2C address |
| `gyro.sample_rate_divider`                      | int    | 0            | 0 - 255; controls how many measured samples are actually outputted (see below) |
| `gyro.dlpf_cfg`                                 | int    | 2            | enum value; controls cutoff frequency for digital low pass filter and also internal sampling rate (see below) |
| `mag.address`                                   | int    | 12           | VCM5883L I2C address |
| `mag.publish_rate`                              | double | 50.0         | VCM5883L publishing frequency |
| `mag.output_data_rate`                          | double | 50.0         | 10.0 / 50.0 / 100.0 / 200.0 Hz |
| `baro.address`                                  | int    | 119          | BMP280 I2C address |
| `baro.publish_rate`                             | double | 10.0         | BMP280 publishing frequency |
| `baro.oversampling_setting`                     | int    | 4            | enum value; controls how many temperature and pressure samples are used for oversampling (see below)|

### More info
`publish_rate`: Sensor output data rate determines how frequently the sensor internally updates its measurement registers. ROS publish_rate determines how frequently this driver reads and publishes those measurements. In general, configure the sensor output data rate to be equal to or greater than the desired publish rate. If the publish rate exceeds the sensor output data rate, the same sensor measurement may be published multiple times.

`gyro.dlpf_cfg`: The gyroscope uses a digital low pass filter and exposes this parameter to give recommended combinations of low pass filter cutoff frequency and internal sample rate. If a very high data output data rate is required, choose `gyro.dlpf_cfg` = 0 for the highest internal sampling rate.

| dlpf_cg param | Low Pass Filter Bandwidth (Hz)| Internal Sample Rate (kHz) |
| ------------- | ----------------------------- | -------------------------- |
|       0       |              256              |             8              |
|       1       |              188              |             1              |
|       2       |               98              |             1              |
|       3       |               42              |             1              |
|       4       |               20              |             1              |
|       5       |               10              |             1              |
|       6       |                5              |             1              |

`gyro.sample_rate_divider`: The gyroscope output data rate is controlled using a sample rate divider, which controls how the internal sample rate is divided down to produce the gyroscope output data rate. The output data rate can be calculated as:
$$
\text{output data rate} = \frac{\text{internal sample rate}}{\text{sample rate divider} + 1}
$$
For example, with a 1 kHz internal sample rate:
- divider = 0 → 1000 Hz output
- divider = 1 → 500 Hz output
- divider = 9 → 100 Hz output

`baro.oversampling_setting`: the BMP280 datasheet has recommended combinations of pressure and temperature oversampling parameters which control the number of samples used in oversampling, which in turn determine the tradeoff between resolution and output data rate. 

| oversampling_setting param | Description | Pressure oversampling | Typical pressure resolution | Temperature oversampling | Typical temperature resolution | Typical output data rate (Hz)|
| -------------------------- | ----------- | --------------------- | --------------------------- | ---------------- | --------------------------------------------- | ------------------------ |
| 0 | Ultra low power       | x1  | 16 bit / 2.62 Pa | x1 | 16 bit / 0.0050 °C | 166.67 |
| 1 | Low power             | x2  | 17 bit / 1.31 Pa | x1 | 16 bit / 0.0050 °C | 125.00 |
| 2 | Standard resolution   | x4  | 18 bit / 0.66 Pa | x1 | 16 bit / 0.0050 °C | 83.33  |
| 3 | High resolution       | x8  | 19 bit / 0.33 Pa | x1 | 16 bit / 0.0050 °C | 50.00  |
| 4 | Ultra high resolution | x16 | 20 bit / 0.16 Pa | x2 | 17 bit / 0.0025 °C | 26.32  |

The sensor does not expose output data rate directly. Instead, it directly depends on the oversampling setting chosen (greater oversampling size takes more time and hence has slower output) as well as standby time, which this library already sets to the minimum (0.5ms) to guarantee the highest possible output data rate. These typical data rate values are listed above.
